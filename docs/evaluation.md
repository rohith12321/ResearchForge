Evaluation
Purpose
The evaluation is intended to examine whether ResearchForge executes reliably, covers the main aspects of a research question, and produces useful evidence-grounded literature synthesis. It also includes an initial comparison with a conventional single-pass RAG output.

The current results are preliminary. They should not be interpreted as a controlled proof that a multi-agent architecture is generally better than conventional RAG.
Initial benchmark
Five AI/ML research questions were used:
1. Retrieval-Augmented Generation (RAG)
2. Reinforcement Learning from Human Feedback (RLHF)
3. Few-shot learning and Model-Agnostic Meta-Learning (MAML)
4. Transformer architectures
5. Large Language Models (LLMs)
The workflow was configured with a maximum of three iterations per question.
Metrics used
Execution success
Checks whether the workflow runs without a runtime failure.
Keyword-based aspect coverage
Checks whether expected topic concepts appear in the generated report. The initial benchmark reported 96.7% average coverage.

This is a keyword-presence measure. It does not establish that the report explains a concept correctly, provides sufficient depth, or supports its claims with evidence.
Citation identifier validity
Checks whether cited paper identifiers correspond to papers retrieved by the Researcher.
Fact-check verdicts
Records the Fact Checker's Supported, Partially Supported, and Unsupported verdicts. These verdicts must be interpreted in light of the current exact-substring validation limitation.
Preliminary benchmark observations
- All five benchmark runs executed without runtime failure.
- Each run reached the configured maximum of three iterations.
- The Fact Checker processed 28 claims.
- None of the 28 claims passed the current strict validation check.
The last result should not be interpreted as evidence that all 28 claims were factually false. The programmatic validation requires an exact substring match between the model-provided quote and the extracted PDF text. Whitespace differences, PDF extraction artifacts, or paraphrasing can cause a quote to fail even when it refers to relevant evidence.

Similarly, reaching the iteration limit indicates that the workflow continued to request follow-up research; it does not by itself show that the final report improved after every iteration.
Preliminary comparison with conventional RAG
A preliminary comparison was conducted using one research question. The conventional single-pass RAG output was compared with the ResearchForge output using a manual five-criterion rubric:
- Topic coverage
- Technical depth
- Discussion of limitations
- Evidence usage
- Citation quality

Each criterion was assigned a score from 0 to 2.
Criterion	Conventional RAG	ResearchForge
Topic coverage	1	2
Technical depth	1	2
Limitations discussion	1	2
Evidence usage	1	1
Citation quality	1	1
Total	5/10	8/10


ResearchForge also cited eight distinct papers in that output, compared with two in the conventional RAG output.

These scores are manual judgments, not scores generated by the automated evaluation code. The two systems retrieved different paper collections, so the comparison does not isolate the effect of the multi-agent workflow. It also uses only one question. The 8/10 versus 5/10 result should therefore be described as a preliminary qualitative comparison, not as a measured improvement in factual accuracy.
Limitations
1. The benchmark contains only five research questions.
2. Keyword-based coverage does not measure semantic correctness or factual support.
3. Exact-substring quote validation is too sensitive to text formatting and paraphrasing.
4. The preliminary RAG comparison uses one question and manual scoring.
5. The compared systems did not use an identical evidence collection.
6. The current results do not provide a controlled measurement of latency, API cost, or retrieval recall.
7. Reaching the iteration limit does not independently demonstrate that iterative refinement improved answer quality.

Next evaluation steps
- Fix quote normalization and introduce a more robust claim-evidence support evaluation.
- Use a larger fixed benchmark with reference evidence.
- Compare baseline RAG and ResearchForge using the same source corpus, retrieval settings, and model configuration wherever possible.
- Add a manual audit of a sample of claims and citations.
- Measure retrieval quality, claim support, coverage, latency, and API cost.
- Report results separately for execution reliability, retrieval quality, evidence support, and final report quality.
